### 踩坑记录（重要，下次复用）

1. **本会话环境注入了 `SERVER__PORT=9098`**，Spring Boot 宽松绑定会把它当成 `server.port`，导致后端去抢 9098（被占用）启动失败。启动后端必须显式传 `--server.port=8080`（或 `unset SERVER__PORT SERVER_PORT`）。
2. 前端 `npm install` 时 esbuild 的 postinstall 做版本校验会 `spawnSync node.exe EBUSY` 失败；解决：`npm install --ignore-scripts`（esbuild 平台二进制已随 optionalDependencies 装好，Vite 可正常跑）。
3. 不要在 `spring-boot:run` 的同时跑 `mvn clean`，会清掉 target 导致 `ClassNotFoundException: com.grainshield.GrainShieldApplication`。
4. 本机无 Docker、无系统级 Java/Maven，一切走上述便携目录（用绝对路径调用）。

## 修复：.vue 文件被透明加密导致 Vite 报 "Element is missing end tag"

**现象**：前端页面报 `[plugin:vite:vue] Element is missing end tag. App.vue:1:20`，Vite 读到的是乱码；但后端正常。

**根因**：项目里 **20 个 `.vue` 文件全部被企业透明加密驱动加密**，文件头为 `%TSD-Header-###%`（IP-guard / 溢信 一类的 DLP 透明加密，本机装有深信服 aTrust/EDR 系列 agent）。驱动**按扩展名策略**只对 `.vue` 加密，`.js/.json/.css/.java` 均为明文。Node/Vite 进程不在解密白名单，故读到密文；Python 进程在白名单，可读到明文。

**关键规律（已实测）**：
1. 用 Python 覆写已有加密文件 → **仍是密文**（加密标记被保留）。
2. **先删除、再由 Python 新建同名文件 → 明文**。← 这是修复手段。
3. bash/Node 视角读始终是密文；Python 视角读始终是明文。
4. `Downloads\grain-shield-system.zip` 里是加密前的明文源码（可用于对照恢复）。
5. git 仓库里的对象本身就是明文（`git show HEAD:frontend/src/App.vue` 返回正常），所以**无需重新提交**。

**修复做法**：Python 脚本遍历 `frontend/src/**/*.vue` → 读出明文 → `os.remove` 原文件 → 以同内容 `open(...,'wb')` 新建 → 回读校验。20/20 成功，之后 Vite 编译 20 个组件全部 200，Chrome 无头截图确认登录页与仪表盘渲染正常。

**备份**：明文副本在 `C:\Users\15015\.workbuddy\binaries\_dl\vue_plaintext_backup\`（保留）。

**风险提示**：若后续用会被加密的编辑器（受 DLP 管控的 IDE）再编辑 `.vue`，可能重新变成密文；届时重跑上述"删除重建"即可。

## 修复：大屏在小屏（1366×768）上拥挤/裁切 → 改为等比缩放

**现象**：用户在自己电脑上看 4 块大屏，标题被截断、顶部导航压在 KPI 上、右侧表格被切掉，"感觉很拥挤"。我复现后确认：我的截图是 1920×1080，用户屏幕是 1366×768，而 `ScreenShell` 布局是 `100vw/100vh` **占满一屏**的弹性结构，屏幕一小就全被压缩变形。

**根因**：大屏应用不该用"占满一屏"的自适应布局，应该用**固定设计画布 + 整体等比缩放**。

**修复（关键）**：
- `screen.css`：`.sk-root` 由 `width:100vw;height:100vh;position:relative` 改为 `position:fixed;inset:0`；新增 `.sk-frame{position:absolute;inset:0}`；`.sk-stage` 改为 **固定 `1920px × 1080px`** + `position:absolute; left:50%;top:50%; transform-origin:center`。
- `ScreenShell.vue`：`fit()` 计算 `scale = Math.min(innerWidth/1920, innerHeight/1080)`，`stageStyle = { transform: 'translate(-50%,-50%) scale(' + scale + ')' }`，并监听 `resize` / `orientationchange` 重算。小屏等比缩小，大屏等比放大，**永远不会挤压变形**。
- 同步把设计基准尺寸整体放大以贴合 1920 画布：header 76→86px、标题 30→34px、KPI padding 12/16→16/20、KPI 图标 44→50、KPI 数值 27→30、主区 gap 12→14、面板头 36→42px、面板标题 15→16px、表格字号/内边距上调、`.sk-big` 30→34px。

**验证**：1366×768 下 4 块大屏均完整显示无裁切（已截图确认）；1920×1080 下也更舒展；`vite build` 通过；`docs/screens/` 4 张交付截图已按新版重拍。
