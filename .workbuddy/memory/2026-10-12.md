## 大屏在真实笔记本视口下的排版修复（核心结论）

### 关键发现：headless 截图的视口补偿
- `chrome --headless=new --window-size=W,H` 得到的 **inner viewport 比窗口小 (22, 98) 像素**。
  即 `--window-size=1366,768` 实际只渲染 **1344×670**。
  之前所有"1366×768"截图都是短了 98px 的，导致我以为页面被裁切 —— **验证标准本身就是错的**。
- 正确做法：窗口尺寸 = 目标视口 + (22, 98)。已固化到 `C:/Users/15015/AppData/Local/Temp/sk_diag/shot.sh`。
- 另外：真实 1366×768 笔记本上，浏览器去掉标签栏+地址栏后**可视高度只有约 610~670px**。
  所以真正的设计基准应是 **1366×610 ~ 1366×670**，而不是 768。

### 量化审计方法（替代"看图识字"）
截图 OCR 读数不可靠。建立了 **POST 回传式审计探针**：
- `public/_audit.html`：iframe 加载 4 屏，逐表测量每列 `box/need/over`，
  遍历 `.sk-root *` 找 `overflow:hidden` 且 scrollHeight>clientHeight 的裁切元素，
  统计每个面板的 `.sk-table__wrap/.plan-box/.veh-wrap/.detail-box` 内容高 vs 可视高，
  再 `fetch(POST)` 到本地小服务落盘 JSON。
- `report_server.js`（Node，端口 5199）+ `audit.sh <W> <H>` 一键跑完。
- 用 Python 解析 JSON 出结论。**这套探针是本轮修布局的关键工具，值得保留复用。**
- 探针文件用完已从 `frontend/public/` 删除（避免污染构建产物）。

### 真实缺陷与修复（按根因分类）
1. **横向文字截断（最普遍）**：`.sk-table` 虽是 `table-layout:fixed`，
   但面板宽仅 ~330px 却塞 4~6 列 → 每列 need > box 最多 66px。
   修复手段（组合）：
   - 删掉语义重复的列（如"起点/终点"已被线路名包含；"起止点"同理）；
   - 重新分配列宽百分比；
   - `th/td` padding 4/8 → 3/7，`.sk-tag` padding 2/9 → 2/7；
   - 三栏比例 `1fr:1.95fr:1fr` → `1.16fr:1.58fr:1.16fr`（把中间地图的余量让给两侧列表）。
2. **字体过小问题**：坚持**不用整体 scale 缩放**，改为原生尺寸铺满 + 三级**高度媒体查询**收紧：
   `max-height:720px / 660px / 650px`，逐级压缩 header 高度、KPI 尺寸、面板 padding、表格字号。
3. **底部面板被压扁导致内容溢出**：把详情的弹性比例调大
   （如总览 `调度建议概览` flex 1.05→1.6、`实时风险告警` 1.15→1.0）。
4. **极矮视口（<620px）特殊处理**：
   - 告警详情"风险原因/处置建议"两块改 `grid-template-columns:1fr 1fr` 并排；
   - 调度"规划路线"独占整行（`.plan-full{grid-column:1/-1}`），去掉重复的"关联告警"行；
   - 执行反馈文案缩短，极矮时只保留一条。
5. **Flex 容器塌高（历史坑，再次确认）**：`.sk-chart` 用 `flex:1` 定位，
   父级若是块级元素或 `align-items:center`，画布高度会塌成 0（环形图空白）。
   必须给父级 `display:flex` + `align-self:stretch` 或 `min-height`。
